# 안내데스크 태블릿 3건 설계 — 접근제어 · 언어 선택 · 개인정보 고지

작성 2026-08-01 · 대상 커밋 `478b694` · 시범운영 전 필수(조달 심사 등급 A1·A2, 기술 격차 C3)

## 배경

구매자(공공조달) 관점 심사에서 계약 불가 사유 2건이 나왔다.

1. `GET /api/desk-sessions`(`server.js:1877-1885`)가 **인증 없이** 전 데스크의 뷰어 토큰(`t`)을 배포한다. 이 토큰
   하나로 진행 중인 승객 대화를 실시간 수신할 수 있고, `desk-end`(`server.js:2927-2931`)로 응대를 원격 종료할 수도
   있다. `deskCtlAllowed`는 빈도만 제한한다. 인터넷에서 URL만 알면 김포공항 전 안내데스크가 열린다.
2. 승객 음성을 수집하면서 고지·동의 문구가 손님 화면 어디에도 없다(grep 0건).

함께 처리하는 기능 격차 1건: 손님이 고를 수 있는 언어가 화면상 3개뿐이다(`desk.html:196-198`). 실효 커버리지는
자동감지로 Soniox 60개 전부지만, RFP 심사는 화면을 본다.

## 운영 전제 (사용자 확정)

- 안내원은 **PC를 켜고 로그인해 세션을 여는 것까지만** 한다. 태블릿은 켠 채로 두고 손대지 않는다.
- 따라서 태블릿의 접근 자격은 **영구적**이어야 하고, 안내원이 재발급·재설정하는 절차가 있으면 안 된다.

이 전제는 현재 구조와 충돌하지 않는다. 뷰어 토큰은 `HMAC(AUTH_SECRET, 'viewer:'+id)`(`server.js:2170-2180`)로
세션마다 고정이라 만료가 없다. 바꿔야 하는 것은 토큰의 수명이 아니라 **토큰을 얻을 수 있는 경로**다.

## ① 접근제어 — 공개 목록에서 토큰 제거

### 현재 태블릿이 토큰을 얻는 두 경로

| 경로 | 토큰 출처 | 인증 | 안내원 조작 |
|---|---|---|---|
| 세션 QR `desk.html?session=..&t=..` | `GET /api/qr?session=..` | **있음** — `viewerAccessOk`(`server.js:2196`) | 0회 (부팅하면 그 데스크로 직행) |
| 랜딩 목록 `desk.html` (세션 없음) | `GET /api/desk-sessions`의 `t` | 없음 | **매 부팅마다 데스크를 탭해서 선택** |

공개 `t`를 쓰는 경로가 오히려 안내원 조작을 요구한다. 목록에서 `t`를 빼면 보안이 닫히면서 운영도 단순해진다.

### 변경

**서버** — `server.js:1884`
```js
.map((s) => ({ id: s.id, title: s.title || '안내데스크', active: ... }));   // t 제거
```
`viewerToken`·`viewerAccessOk`·`/api/qr` 게이트는 그대로 둔다. 목록은 계속 공개다 — id·제목·가동 여부는
비밀이 아니고, 관리자가 데스크 상태를 확인하는 데 쓰인다.

**클라이언트** — `desk.html` `loadRooms()`(`:694-716`)
- 행을 클릭 불가로 바꾼다. `sessionId`/`token` 대입 코드를 제거한다.
- 목록 아래에 안내 1줄: "설치용 QR은 관리자에게 요청하세요 / Ask staff for the setup QR"
- `active` 표시는 유지(안내원 준비 중 태그).

**프로비저닝(운영 절차, 코드 아님)**
관리자가 관리자 화면에서 데스크 세션의 QR을 열고, 태블릿으로 1회 스캔한다.
- 안드로이드 키오스크 셸: `MainActivity.kt:164`의 URL 입력에 붙여넣기
- iPad Safari: 열고 '홈 화면에 추가'

### 미채택 — 기기 페어링(대안 B)

관리자가 페어링 코드를 발급하고 태블릿이 1회 입력해 기기별 토큰을 받는 방식. URL에서 토큰이 사라져 화면 캡처
유출이 막히고 분실 기기를 개별 폐기할 수 있다. 1~2일. **시범 후, 보안성 검토가 개별 폐기를 요구하면 그때 한다.**
지금은 위 변경만으로 "인터넷에서 원격으로" 라는 조건이 사라지고, 남는 위협은 태블릿 물리 접근이다.

### 회귀 테스트 (`test/desk-access.test.mjs`, 신규)

1. `GET /api/desk-sessions` 응답의 모든 항목에 `t` 필드가 **없다**.
2. 로그인 없이 `/api/qr?session=<deskId>` → 403.
3. 관리자 쿠키로 `/api/qr?session=<deskId>` → `url`에 `&t=` 포함.
4. 그 토큰으로 `/ws/viewer` 접속 성공, 토큰 없이는 실패.

### 기존 테스트 수정 (필수)

`test/desk-pipeline.test.mjs:36-39`가 공개 목록에서 토큰을 가져온다. 관리자 쿠키로 `/api/qr?session=..`를
호출해 URL에서 `t`를 파싱하도록 바꾼다. 같은 커밋에서 처리하지 않으면 테스트가 깨진다.

## ② 언어 선택 — 스크롤 리스트 12개

드럼 휠 대신 스크롤 리스트로 간다. 김포 국제선은 en/ja/zh가 대다수인데, 휠은 그 손님까지 스핀+확인 2동작을
요구한다. 리스트는 상위 3개가 스크롤 없이 보여 **흔한 경우 1탭**이고 드문 언어만 스크롤한다.

### 노출 언어 12개 (순서 = 표시 순서)

`en · ja · zh · vi · th · id · ru · tl · es · fr · de · ar`

전부 `SONIOX_LANGS`(60개) 및 `desk.html`의 `LANGNAME` 자국어 표기를 갖고 있음을 확인했다.

> **몽골어(mn)는 제외한다.** `LANGNAME`에는 있으나 Soniox stt-rt-v5 지원 목록에 없어 명시 선택도 자동감지도
> 불가하다. 엔진 제약이므로 다른 벤더로 바꿔도 동일하다. 국내 관행상 "13개 언어"로 표기하는 사례가 많은데,
> 제안서에는 숫자 대신 실제 지원 목록을 쓴다.

### 화면 (`desk.html` `#touchWrap`)

- `#langBtns`(버튼 3개) → `#langList`(세로 스크롤 리스트)로 교체.
- 행: 자국어 표기 1줄(`LANGNAME`), 최소 높이 56px, 전체 폭, 하단 1px 구분선.
- 최상단 3행(en/ja/zh)이 스크롤 없이 보이도록 리스트 높이를 잡는다.
- 리스트 하단 고정 행: 마이크 아이콘 + "그냥 말씀하세요 / Just speak"(`startWithLang('auto')`).
- 글자 크기 슬라이더(`fs`) 적용 대상에 포함한다.

### 서버 — 조용한 영어 폴백 제거

`server.js:3913-3920` 현재:
```js
const auto = B === 'auto';
const lang = auto ? null : (GUEST_LANGS.includes(B) ? B : 'en');
...
phase = 'active'; lockedB = lang; autoDetect = auto;
```
`GUEST_LANGS`(10개)에 없는 언어를 고르면 **아무 안내 없이 영어로 바뀐다.** 새 12개 목록의 tl·ar가 여기 걸린다.

변경:
```js
// 명시 선택은 엔진 지원 전체(SONIOX_LANGS 60개)로 검증한다. 미지원 값이면 영어로 바꾸지 않고
// 자동감지로 넘긴다 — 손님이 고른 언어가 아닌 언어로 조용히 통역되는 것보다 낫다.
const picked = B !== 'auto' && SONIOX_LANGS.includes(B) ? B : null;
const auto = !picked;          // 'auto' 선택 또는 미지원 값 → 첫 발화로 감지
const lang = picked;
```
이후 `lockedB = lang; autoDetect = auto;`는 그대로 동작한다. `phase === 'active' && !auto && lang === lockedB`
(같은 언어 재탭 무시) 가드도 그대로다.

**`GUEST_LANGS`는 건드리지 않는다** — 이 배열은 자동감지 `language_hints` 전용이고(`server.js:3943`,
`3949`), 늘리면 힌트가 희석돼 감지 정확도가 떨어진다. 명시 선택과 자동감지 힌트는 서로 다른 관심사다.

## ③ 개인정보 고지 — 언어 선택 후 모달

### 흐름

```
대기 화면(언어 리스트)  →  [언어 탭]  →  고지 모달(그 언어)  →  [동의하고 시작]  →  발화 대기
```

언어를 먼저 고르게 해서 **손님이 읽을 수 있는 언어로** 고지한다. 손님당 1회이며, 응대가 끝나 대기 화면으로
돌아오면 다음 손님에게 다시 표시된다.

### 문구

한국어 원문(사용자 확정):
> 원활한 번역 서비스를 위해 음성 데이터가 외부 음성인식 서비스에서 처리될 수 있으며, 서비스 품질 개선을 위해
> 대화 내용이 저장될 수 있습니다.

`desk.html`의 `UI` 사전에 3개 키를 추가하고 `t()`로 렌더한다.

| 키 | 내용 |
|---|---|
| `consentTitle` | 짧은 제목 — ko "안내" / en "Privacy notice" |
| `consentBody` | 위 문구의 12개 언어 번역 |
| `consentBtn` | ko "동의하고 시작" / en "Agree and start" |

영어 기준역(나머지 11개 언어는 이 어조로 맞춘다):
> To provide translation, your voice data may be processed by an external speech recognition service, and
> conversation content may be stored to improve service quality.

번역문은 구현 시 작성해 `UI` 사전에 넣고, 태블릿 실화면에서 12개 언어 모두 줄바꿈·잘림 없이 표시되는지
확인한다(아랍어·태국어는 줄높이가 다르다).

**아랍어(ar)**: 모달 컨테이너에 `dir="rtl"`을 설정한다.

**자동감지 경로**: 언어가 정해지지 않았으므로 모달을 **한국어 + 영어 병기**로 표시한다.

### 동의 기록

뷰어가 보내는 `desk-start`에 `consent: true`를 실어 보내고, 서버는 응대 아카이브 시
`deskLog[].consentAt = Date.now()`를 기록한다(`server.js:3883`). 감사 시 "고지·동의 후 시작했다"의 증거가
된다. 값이 없는 과거 기록은 그대로 둔다(하위 호환).

### 범위 밖 (운영 산출물)

이 모달은 **화면 고지**이지 처리방침이 아니다. 다음은 코드가 아니라 기관이 준비해야 한다.

- 수집 항목·목적·보유기간·국외이전 3사(Soniox / OpenAI / Cartesia, 미국)·문의처를 담은 기관 개인정보 처리방침 개정
- 데스크 카운터 게시물
- 개인정보보호법 제15조 수집 근거와 제28조의8 국외이전 근거의 법률 검토

> 문구와 법적 근거는 기관 개인정보 담당 부서 검토를 받아야 한다. 이 문서의 문안은 검토용 초안이다.

### "AI 학습" 표현을 쓰지 않은 이유

초안에 "AI 학습을 위해"가 있었으나 뺐다. 실제로 이 데이터로 모델을 학습시키지 않는다 — 벤더 처리와 운영
통계·시범 평가용 보관이다. 사실과 다를 뿐 아니라, "AI 학습"이라고 쓰면 별도 동의가 필요한 처리로 해석될
여지가 커진다.

## 함께 확인해야 할 운영 사항 (코드 밖)

**노트북을 덮으면 데스크가 오프라인이 된다.** 덮개를 닫으면 OS가 절전에 들어가 마이크 캡처와 WebSocket이
끊기고, 손님 화면은 "안내원 준비 중"이 되어 통역을 시작할 수 없다. 코드로 우회할 수 없다 — 전원 설정에서
"덮개를 닫을 때: 아무 것도 안 함"으로 두거나, 덮지 말고 화면만 끄도록 운영 지침에 넣어야 한다.
